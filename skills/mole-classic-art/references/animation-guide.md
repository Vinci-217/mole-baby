# 原动作优先的拉姆动画

动画任务先核对原 SWF 的完整动作，不可只从已有九行小图集推断原游戏没有相应动作。`lamubone.swf` 和各神力 SWF 都有 `football`；它包含身体、眼睛、叶冠和球的协作，可直接用于玩球。原帧、源哈希、导出与小尺寸对照见仓库 `research/v21-original-actions.md`。

1. 逐帧看完整演出，再选片段和播放时长。嵌套静态容器需要展开子时间轴，不能只取第一帧；保持原24fps、原停留帧和动作结束。
2. 身体、球和叶冠优先来自同一原帧。需要适配桌面范围时，一起移动或缩放；原接触保持同一时刻，不独立造一条脱离身体的球轨迹。
3. 表情要匹配状态。`happy` 笑眼不代替困倦眼睑；摸头保留熟悉的大眼睛也能靠抬眼、身体跟手和轻蹭回应。不要长期固定一张人造闭眼脸。
4. 缺少完整官方睡眠片段时，明确记录适配：原困倦眼睑、原嘴型的小幅张合、原 Z 字粒子；种子保持直立花盆，飞行形态保留缓慢悬浮。新的绘制需求仍使用图片模型，不能程序重画角色。
5. 用实际100px宠物检验。动作可使用透明留白；不得让远处道具把角色一起缩成小点。检查嘴巴位于脸内、眼线清楚、道具接触、身体轮廓、四种配色、动画结束、拖拽后的连续进度和减少动态效果。
6. 录制实际运行的动画，截图只能检查某一帧。发布前看完整录屏，再核对 Windows 与两种 Mac 成品中的实际动画。

## 心情和装扮的补充

- 心情动作先查看原 happy/angry/boring。开心可以采用原开心脸；摸头保留大眼睛。负面情绪选短暂皱眉，先查看是否含大嘴喊叫等不适合常驻陪伴的后段。剪辑、反向和改节奏都明确标注为适配。
- 低精力、低心情和用户表达难过是不同输入，不把它们混成开心或生气。自动动作保持低频，尊重安静和忙碌，不伪造照料奖励或共同经历。
- 睡眠的呼吸幅度小，嘴型别占满脸；原 Z 字从当前身体外侧发出，不穿过眼睛。静态截图之外，检查整个呼吸周期。
- 配饰从完整 sprite 导出，舞台缩略图可能裁掉帽檐。逐帧用身体遮罩定位，加入身体的同一变换层；花盆装饰和身体装饰分别挂接。换装不重画身体，四种颜色不染配饰。
- 试戴与实际穿戴分开。检查静止/暂停时换装能立即出现，购买按钮在两个目标窗口完整可见；全套衣服另需背面、分层遮挡与各动作姿态，不能拿正面图贴所有帧。参考 [装扮实现说明](../../../docs/WARDROBE.md)。

## 服饰动画与脸部检查（v0.24）

商品 `petcloth/swf/cloth` 和行走装扮 `petcloth/swf2` 不是同一用途。先检查原控制器 ActionMC3/petBone3、阶段标签、完整显示列表与装扮层；只拿 sprite2 可能漏掉星星或帽檐。Move没有HasCharacter时必须保留当前characterId。全身变装不能当透明衣服直接叠脸。

装扮应和身体共享源帧、动作时钟与变换父级；足球/心情图集去重后的格号不能作为原源帧。帽、兜帽、手持物分别挂接，书本不能遮住拉姆偏低的眼睛。遮冠服饰必须保留原瞳孔层；不能从白色像素推算头角度，球和牙齿都会误判。换色图集加载期间不能用旧颜色标记新颜色已经绘制完成。

缺少种子、神力或动作源帧时，明确记录原姿态回退和安装适配，不把它描述成官方逐形态专属动作。至少复核8形态×4色，核对身体脸部像素、衣服不染色、眼白遮挡和100px实际录屏；玩球/照料中穿脱不能重置动作时钟。导出与限制范例见仓库 `public/assets/original/wardrobe-motion/README.md`。
