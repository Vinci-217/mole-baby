# 原动作优先的拉姆动画

## 变身与连续绘制的审核

- 当前变身方向：先单独绘制变身后的动物或植物给用户选择；动画再通过一团短暂烟雾遮住原角色，烟雾消散后显示目标，停留数秒，再由烟雾遮住目标并恢复原角色。烟雾要覆盖当前阶段和装扮的完整轮廓，允许不同阶段共用同一目标；不要用附耳朵或在头上放树来冒充变成另一个物体。尚未实现或得到用户认可的内容标记为预览。
- 原初级/中级/高级身体用明亮平面色块、同色暗面和短高光，身体轮廓不画黑色描边；黑色瞳孔保留。叶片按照目标阶段原图处理，切勿将道具或场景的深色边线套到身体上。变身前后均保持宠物自身轮廓、眼睛比例、色彩身份和统一站位。
- 为每一段准备更多互相衔接、确有形变的新绘姿态：蓄力、变形中间、显形、反应、恢复，逐帧核对锚点和表情；变身是同一角色原地变化，不能并排放一个动物充当结果。原身体、模型新姿态与动画后期编排分别保留来源和数量。
- 不以导出 GIF 的帧数冒充绘制帧数。重复、倒放、程序渐变/插值帧单独列出，报告连续绘制的独立姿态数量及每张停留时间；4张图片切换即便导出24fps也不能称为24张流畅逐帧。先实看完整播放、100px尺寸和逐帧截图，检查身份漂移、轮廓黑线、边缘、落点漂移、眼部重影和截断后再展示。
- 生成时附多张已实际核对的原角色与同阶段动作参考，逐张说明用途；官方原动作、适配和原创候选明确区分，不能把无年代证明的参考统一标为2008—2010年素材。

## v38：先看接点，再看完整动作

- 原角色参考见本目录`v38/original-reference.png`。原身体帧继续逐帧使用，不用新模型重画眼睛、嘴或叶片比例。
- **叶柄不是“绿色像素碰到身体的最深处”。** 外侧叶片可能挡住身体；把那个交叠处当关节，会把整个叶冠挂偏。v37因此失败。应先在原图标出双叶中央叶柄，再通过面部地标定位同一头部接点，接点略埋入身体以防白缝；叶冠比例按初级静止头部换算，不沿用较小的中级身体显示宽度；从正面、斜面、侧面逐帧核对。
- 身体像素完全一致、帧号同步等自动检查只能证明没有改坏身体，不能证明叶子自然。还必须看整体轮廓、叶片生长方向、回摆幅度、接点与动画开头/结尾的衔接。
- 同一动作的关键帧使用同一比例和注册基准，不能把每帧外接框分别放大到同样大小。旋风要能从小风旋长大；陨石要先入射、再落地，不能把飞行帧也强行贴到地面。
- 新课程与技能：按预备、接触/施放、结果、收尾编排。翻页要换真实页形；送餐要有盖盘、开盖/上菜、收空碗；魔术以拉姆本体变身、停留和变回为方向。不能只晃动一张不变的图。
- 原素材身体动作与新道具的关键帧分开记录；模型绘制3–4个关键姿态、离线编排成48/72帧，不写成“每张都是官方原帧”或“全部手绘72张”。运行时按24fps直接取透明图集。
- 法术将色彩与能量集中在身体右下方，保持眼睛、嘴和主要轮廓可读。没有核对到《摩尔勇士》原帧前，只能标记为新绘候选，后续拿到可核对参考后再逐步修订。
- 家具缩到实际尺寸复核：少量大色块、轮廓清楚、无毛边光晕；证书留白给应用排字。证书/壁画/钟属于墙面，地毯/花盆/桌椅属于地面，不能靠拖拽越过类型限制。

动画任务先核对原 SWF 的完整动作，不可只从已有九行小图集推断原游戏没有相应动作。`lamubone.swf` 和各神力 SWF 都有 `football`；它包含身体、眼睛、叶冠和球的协作，可直接用于玩球。原帧、源哈希、导出与小尺寸对照见仓库 `research/v21-original-actions.md`。

1. 逐帧看完整演出，再选片段和播放时长。嵌套静态容器需要展开子时间轴，不能只取第一帧；保持原24fps、原停留帧和动作结束。
2. 身体、球和叶冠优先来自同一原帧。需要适配桌面范围时，一起移动或缩放；原接触保持同一时刻，不独立造一条脱离身体的球轨迹。
3. 表情要匹配状态。`happy` 笑眼不代替困倦眼睑；摸头保留熟悉的大眼睛也能靠抬眼、身体跟手和轻蹭回应。不要长期固定一张人造闭眼脸。
4. 缺少完整官方睡眠片段时，明确记录适配：原困倦眼睑、原嘴型的小幅张合、原 Z 字粒子；种子保持直立花盆，飞行形态保留缓慢悬浮。新的绘制需求仍使用图片模型，不能程序重画角色。
5. 用实际100px宠物检验。动作可使用透明留白；不得让远处道具把角色一起缩成小点。检查嘴巴位于脸内、眼线清楚、道具接触、身体轮廓、四种配色、动画结束、拖拽后的连续进度和减少动态效果。
6. 录制实际运行的动画，截图只能检查某一帧。发布前看完整录屏，再核对 Windows 与两种 Mac 成品中的实际动画。

## 心情和装扮的补充

- 心情动作先查看原 happy/angry/boring。开心可以采用原开心脸；摸头保留大眼睛。负面情绪选短暂皱眉，先查看是否含大嘴喊叫等不适合常驻陪伴的后段。剪辑、反向和改节奏都明确标注为适配。
- 低精力、低心情和用户表达难过是不同输入，不把它们混成开心或生气。自动动作保持低频，尊重安静和忙碌，不伪造照料奖励或共同经历。
- 睡眠的呼吸幅度小，嘴型别占满脸；原 Z 字从当前身体外侧发出，不穿过眼睛。静态截图之外，检查整个呼吸周期。
- 配饰从完整 sprite 导出，舞台缩略图可能裁掉帽檐。逐帧用身体遮罩定位，加入身体的同一变换层；花盆装饰和身体装饰分别挂接。换装不重画身体，四种颜色不染配饰。
- 试戴与实际穿戴分开。检查静止/暂停时换装能立即出现，购买按钮在两个目标窗口完整可见；全套衣服另需背面、分层遮挡与各动作姿态，不能拿正面图贴所有帧。参考 [装扮实现说明](../../../docs/WARDROBE.md)。

## 服饰动画与脸部检查（v0.24）

商品 `petcloth/swf/cloth` 和行走装扮 `petcloth/swf2` 不是同一用途。先检查原控制器 ActionMC3/petBone3、阶段标签、完整显示列表与装扮层；只拿 sprite2 可能漏掉星星或帽檐。Move没有HasCharacter时必须保留当前characterId。全身变装不能当透明衣服直接叠脸。

装扮应和身体共享源帧、动作时钟与变换父级；足球/心情图集去重后的格号不能作为原源帧。帽、兜帽、手持物分别挂接，书本不能遮住拉姆偏低的眼睛。遮冠服饰必须保留原瞳孔层；不能从白色像素推算头角度，球和牙齿都会误判。换色图集加载期间不能用旧颜色标记新颜色已经绘制完成。

缺少种子、神力或动作源帧时，明确记录原姿态回退和安装适配，不把它描述成官方逐形态专属动作。至少复核8形态×4色，核对身体脸部像素、衣服不染色、眼白遮挡和100px实际录屏；玩球/照料中穿脱不能重置动作时钟。导出与限制范例见仓库 `public/assets/original/wardrobe-motion/README.md`。

## 小尺寸嘴眼与固定服饰校准（v0.26）

- 导出后按100px实际画面审核。原素材也可能包含夸张大嘴、侧脸或挤压；适合完整演出，不一定适合桌面的每一口食物。温和照料可保留原正常身体、眼睛和原小嘴形，明确记录为适配，不声称是官方独立动作。
- 原753偏平，35/1726是短睡眼；不能把一个完整双眼图形放到接近整张脸的宽度。眼区52%的跨度、睡嘴6.5%和吃喝嘴9%是本版的校准值，需要同时检查四种颜色与种子高眼位，不是通用官方比例。
- 每件/每形态只在中性姿态校准一次服饰比例。原姿态变化保留；禁止每帧按服饰外框重新缩放，帽耳、书页、羽毛改变外框不应让整件衣服抽动。
- 种子兜帽开口对齐靠上的原眼睛，普通帽檐留在眼睛上方；同时看完整帽子，不能为了通过遮眼测试把空兜帽悬在头上。
- 相互接触的道具与嘴、身体使用共同事件时钟。魔法换装只改变临时视觉，不更改真实穿戴和所有权；结束恢复，用户打断也要恢复。出游保持归期与召回入口，不能把宠物丢进用户找不到的地方。

- 完整录屏还要检查身体转向时的帽子朝向。缺少football服饰骨骼时，可从原SWF眼睛symbol的放置矩阵和局部轴导出头部挂接，沿身体/球共同相机投影；不能从画面白色像素猜方向，足球和牙齿会误导。缺少可见眼睛的帧明确记录身体空间插值，手持书/魔杖可先放到身旁。
