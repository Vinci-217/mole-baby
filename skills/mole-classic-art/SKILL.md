# 拉姆桌宠的原页游风格美术

此技能把可观察的画法整理为参考引导的生成与审核流程。它不训练模型，也不代表官方授权。素材来源见仓库根目录 `ASSETS.md`。`references/` 相对本技能目录解析；`public/` 与 `ASSETS.md` 相对仓库根目录解析。

当前项目允许原创背景、UI、图标和标识，允许与已有素材混用；不要求复刻原场景或逐像素照搬面板。拉姆本体继续使用现有原角色图集，保持原来的形态与四种配色。以用户当前要求为准，不能把某一版“全部使用原图”的选择当作永久限制。

## 先看图，再写提示词

涉及角色动作时，先读 [原动作与动画复核](references/animation-guide.md)，检查对应的原 SWF 完整时间轴与实际录屏，再决定使用原片或生成新动作。

本轮可直接使用[原角色与身体原帧参考板](references/v38/original-reference.png)、[课程/打工道具关键帧](references/v38/study-service-keyframes.png)、[法术关键帧候选](references/v38/elemental-keyframes.png)和[迭代记录](references/iteration-log.md)。新法术是自行绘制的候选，尚未核对到《摩尔勇士》的官方完整技能原帧，不能把游戏名称当作已经验证的素材来源。

1. 先读 `references/style-guide.md`，再实际查看至少三类参考：场景、UI、道具。任务含角色时加看原角色图。只读名称或来源清单不能代替看图。
2. 最低参考组合：`public/assets/original/scenes/ramu-home.png`、`public/assets/original/ui/reference-pet-panel.png`、`public/assets/original/items/180017.png`。背景任务再看 `scenes/lake-cabin.png` 或 `scenes/ramu-school.png`，避免把一间房的构图误当成整个游戏的画风。
3. 用五行记录本次参考的轮廓、形状、色面、高光与空间安排；写明本次要新设计的内容、保持不变的角色和交互留白。

## 生成

### 优先复用原素材和共用图层

- 新美术先检查现有原版素材、完整原动作与来源记录；家具、小屋背景、拉姆原生技能优先搜集并使用可核对的原素材，缺失时说明缺口，不能直接用新绘候选冒充原版。
- 设计前先列出哪些内容跨阶段、颜色、课程和动作共用。把原角色、烟雾/闪光等遮挡、变身目标、道具、装饰、UI 分成独立资源；不要为每个阶段重画一套相同过程。
- 变魔术采用共用不透明烟雾遮盖后切换目标；恢复时再次播放同一套烟雾，再显示当前阶段与当前配色的原角色。目标没有阶段差异时，共用同一个目标资源，不把叶冠、身体或颜色烘焙进烟雾。
- 共用资源记录统一坐标、缩放、落点、遮挡时点和播放时序；用最大叶冠、最宽身体与目标轮廓验证切换帧的完整覆盖，不能只检查单一中级形态。装扮需另外核对，未验证时明确范围。
- 状态切换和玩法逻辑不写进图片；换阶段或配色应只换角色输入。帧表原图、共用 PNG、时序配置、可重现的预览导出脚本与来源一并保留，避免后续迭代依赖重新生成整段动画。
- 区分新绘姿态数、复用次数、编排时间片与 GIF 编码帧数；不能把共用烟雾重复播放、停留或合成后的输出帧全部算作独立绘制。


- 使用可用的 `image_gen` 图片生成工具；不要用 SVG、Canvas 绘画代码或程序几何拼图代替图片模型绘制角色或插画。现有原拉姆的 Canvas 图集播放和配色可以保留。
- 把已经查看过的本地参考通过工具的参考图片参数提供给模型，并明确每张图只负责哪些特征。背景参考负责画法，UI 参考负责色框与高光，角色参考负责形态；不要让模型把完整原面板或角色印进背景。
- 从 `references/prompt-templates.md` 选用对应模板。给出具体主体、构图、留白、颜色、勾线与硬边阴影，不只写“摩尔庄园风格”“可爱”或“怀旧”。
- 新背景使用不透明输出；道具、按钮、独立装饰需要真正透明背景，设置 `transparent_background: true`，不要让模型绘出棋盘格。
- 背景不生成角色、文字、按钮、Logo 或 HUD。UI 图片只画底板与装饰，业务标签由 HTML 排版。需要新增 Logo 时单独生成图形，中文字标另排，避免乱码。
- 先生成一张候选并检查，再决定是否修订。修订使用图片编辑工具，并提供上一张图及相关原图参考；指出具体缺陷，例如“删除连续木纹和柔光，把桌面改成三块硬边黄色色面”。
- 若用户要求先发布当前版本再生成，先完成约定的发布与构建；准备提示词可以提前进行，实际图片生成必须等到构建完成。

## 复核与接入

用原图和候选图并排检查以下项目；任一主要项失败就先修图，不能用更多滤镜、阴影或 UI 遮挡掩盖差异。

| 项目 | 合格表现 |
| --- | --- |
| 轮廓与比例 | 大形状略不对称，圆润中带短折线；物体简化夸张，轮廓缩小后仍清楚。 |
| 勾线 | 连贯深棕或同色深描边；主要轮廓清楚，内部结构少而准，不用密集细刻线。 |
| 色面与光 | 明亮局部色，每种材质约 2–4 档大色面；硬边投影、短高光，不靠写实纹理和体积光。 |
| 空间 | 轻俯视、玩具舞台感，前后靠遮挡与大小区分；留有角色活动和界面区域。 |
| 与角色同屏 | 原拉姆的叶片、眼睛和身体轮廓能读清；新背景的对比与细节不抢走焦点。 |
| 产品可用性 | 以实际窗口尺寸检查裁切、底栏、弹窗、字幕与角色站位；图标在 32–64 px 仍可辨。 |

背景至少在 1180 × 820 和 1000 × 720 窗口截图检查。底部约 16% 与中央下部保持低细节；这些比例是本项目起点，接入时按实际布局调整。透明素材要检查边缘白晕、截断与阴影外溢。

落盘时使用语义文件名，并记录生成日期、模型工具、参考路径、完整提示词、用途、透明设置、尺寸和人工修改。原素材来源与生成素材来源分开记录，不把新图写成原客户端导出。确认后再更新资源引用，完成相应构建和界面检查；不修改存档结构来配合换皮。
