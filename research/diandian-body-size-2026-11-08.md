# 点点拉姆装身体尺寸修正

用户指出上一轮摸头预览中的点点装明显偏小。原检查只确认加载、有效几何与服装不消失，没有验证真正身体的可见尺寸，遗漏了这个问题。

## 原因与原素材证据

- 原件：`resource/petcloth/swf2/1200113.swf`，SHA-256 `05c32a65e4785b61449b0db0b82d529cf45a55c1a692653feadf91f53f6fb9f9`。
- 根类 `_1200113_fla.sprite322_1`（sprite 305）选择 level2；方向类 sprite 304。
- 正面 petBody 是 sprite 30，里面的 sprite 25 同时放置身体、叶子、蝴蝶结和飘带；不能用这个组合的外接矩形当作身体。
- 正面/左/右的实际身体都是 petBody 的 child 0 / child 0（sprite 5，shape 4）。shape 4 的源矩形是 twips `[-3,-112,446,383]`，保留原生父级坐标变换后，正面参考宽约 22.75；旧容器参考宽 55.95。
- 同一实际超级拉姆、相同显示大小下，从眼睛位置寻找身体实心横截面：旧版为 72 像素，对照目标 177.08；修正后为 177 像素。测量独立于播放器自报的 petBody 宽度，旧版自报宽度也能达标，所以仅看注册矩形不足以发现问题。

## 实现

- 在 `scripts/art/embedded-original/body-registration.json` 保存与源 SHA 绑定的三种方向身体路径。素材生成脚本会验证指纹并写入 manifest，不改原始 SWF。
- 控制器使用该真实身体节点注册尺寸，同时给项目适配的摸头动作报告实时身体位置；整体服装继续沿用原版时间轴、矩阵和装饰比例。
- 一次注册后固定缩放与落脚点，方向变化不重新适配全外框。其他装扮与道具没有新增路径，继续使用各自的原有身体骨骼/节点。
- 播放器缓存标识 v5 → v6，模板与随包副本同步。
- 独立试衣页支持 `?preview=wardrobe&form=super&outfit=1200113`，打开就能看到本次修改，不访问或重置正式存档。

## 验证和范围

- TypeScript 与生产构建通过；499 项 Vitest、166 项 Node 测试通过。
- `scripts/outfit-body-size-regression.cjs`：先路由旧控制器复现，再在八种成年实际形态下测量真实像素；每种形态检查原版左/右/正面姿势和注册稳定性，全部通过。不是声称源 SWF 有八套不同阶段的衣服：按原要求，点点装仍采用原版初级完整外观。
- 六套服装的完整摸头流程通过：点点、抛抛球、幽灵、金元宝、银元宝、猫咪。保留装扮/原播放器且动作正常结束；检查了这些组合的画面。
- Linux Electron 的实际自定义协议、透明窗口、屏幕锚点与穿衣摸头回归通过。没有声称进行了 Windows/macOS/Android 真机测试。
- 对照 GIF 由真实试衣页面录像生成，旧/新两侧使用相同形态、CSS 尺寸与原件；摸头依然是项目适配，走动仍是原版服装时间轴。
- 本轮未推送、打标签、发 Release 或更新 latest。存档路径、键、成长、颜色与记忆逻辑未改。

输出：`artifacts/outfit-size/body-size-checks.json`、`before-measurement.json`、`点点拉姆装大小修复对照.gif`；预览分支保留审阅。
