## “可可果”是否正确

正确。原 XML `ID="180027" Name="可可果"`，属性是 `Hungry="50" Thirsty="0" Sanitary="0" Spirit="0"`。它用于饱食，不是饮料或清洁剂。原配置中 `180028` 是“咕咕果”（口渴属性 +50），`180029` 是“爽爽果”（清洁 +50），`180030` 是“开心果”（心情 +50）；四个图案不能互相替代。

v0.4 的“可可果 +16 饱食、8 豆”“熊熊饼干 +26 饱食、12 豆”“浆果果汁 +18 饱食、15 豆”是桌宠旧数值。v0.5 将效果对齐原配置：可可果饱食 +50，熊熊饼干饱食 +30 / 15 豆，浆果果汁水分 +50 / 20 豆。旧的存档 ID `berry` / `biscuit` / `juice` 保持不变，避免玩家背包或小游戏奖励丢失。

## 原版状态依据与桌宠适配

XML 顶部原注释：`Attr 0饥饿 1口渴 2清洁 3心情 4健康 5治疗 6复活`。因此本项目恢复饱食、水分、清洁、心情、健康五项状态，并使用对应用品。代码里的 `hunger` / `thirst` 数值越高表示越饱 / 水分越足。

本次没有找到可以可靠复现全部原客户端状态切换的完整服务端阈值，以下阈值和时间变化均为本项目规则，不宣传为原版判定：

| 可见状态 | 本项目触发条件 | 对应照料 |
| --- | --- | --- |
| 睡梦中 | 玩家已点击休息 | 持续恢复精力，显示闭眼与叫醒入口 |
| 生病了 | 健康 ≤35 | 饮食与清洁照料，或使用万能药水 |
| 肚子饿了 | 饱食 <30 | 食物 |
| 口渴了 | 水分 <30 | 饮品 |
| 需要清洁 | 清洁 <30 | 清洁用品 |
| 有点难过 | 心情 <30 | 摸摸、小游戏或增加心情的用品 |
| 有点困了 | 精力 <25 | 休息 |
| 状态很好 | 以上均未触发 | 正常陪伴 |

同时触发时按上表顺序显示主要状态；其他指标仍可在状态面板查看。精力、主动睡眠和办公提醒是桌面陪伴功能。健康在长期缺少饮食或清洁时缓慢降低，最低为 1，不会死亡或丢失角色；持续良好照料每小时恢复 2 点。没有接入原游戏的复活、付费超级拉姆或变色丸，也不会增加四种基础色之外的第五种可选色。

存档仍为 version 1。导入旧存档时只新增水分（82）、健康（100）与新商品空槽，原名字、颜色、时间、成长、摩尔豆、背包数量和游戏进度完整保留；随后应用正常的离线变化。导入数值非法、未知用品或重复别名的存档会拒绝，避免悄悄吞掉物品。
