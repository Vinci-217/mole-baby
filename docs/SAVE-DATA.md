# 存档、回忆与升级缓存

拉姆与回忆保存在本机。v0.32 沿用原存档目录、`ramu-house-save-v1` 键、创建时间和回忆键，不移动、不重建已有玩家的数据。待办、最高成长进度和数值记录是可选新增字段；旧存档缺少它们也能读取。

| 版本 | 默认数据位置 |
| --- | --- |
| Windows 常规版 | `%APPDATA%\mole-baby` |
| Windows 兼容版 | `%APPDATA%\mole-baby-legacy`（既有独立渠道） |
| macOS | `~/Library/Application Support/mole-baby` |
| Android / HarmonyOS 4.x | 应用私有目录，SharedPreferences `mole-pet.xml`，系统保护访问 |
| 浏览器网页 | 当前站点的浏览器本地存储，与其他域名或桌面版不共用 |

桌面版会优先沿用有旧数据的 `mole-baby`、`拉姆陪伴` 或原 Electron 用户目录；上表不是要求把旧文件挪过去。开发版或明确使用 `--user-data-dir` 的测试有自己的位置。宠物数值在 Chromium 的 `Local Storage`，回忆使用以创建时间关联的 `ramu-companion-memory-v1:*`；导入的个人音乐在 IndexedDB。不要直接编辑或只复制某个 LevelDB 文件。

调配药水并使用后的自定义颜色保存在原存档的 `color` 字段，不按日期还原。换色时先同步保存，成功后再播放换色动作；保存失败会保留原色与药水。桌面版同时请求 Chromium 刷新存储，退出和更新前也保存快照。留言板窗口只提交留言，不会覆盖颜色、成长或库存。

最稳妥的备份方式：小屋 → 设置 → 导出存档。导出的 JSON 包含身份、成长与解锁、库存、课程、家具、待办、数值记录和回忆。升级前可另外保留一份备份。若原数据无法完整读取，新版会保留原记录，提供原始导出与有效备份恢复入口，避免误领养覆盖。

安卓包名和固定签名延续已有正式预览版，可覆盖安装；不要卸载或清除应用数据。较早的 `.dev` 开发版属于另一包名，须先导出再导入。HarmonyOS NEXT（原生鸿蒙）不能直接运行安卓 APK，本次适配目标是支持 APK 的 HarmonyOS 4.x。

更新缓存与临时下载已经存于系统管理的用户数据/缓存目录。Mac 的手动更新下载在同一用户目录的 `update-downloads`；Windows 安装版沿用更新器自己的私有缓存。它们不与宠物存档混用，下载有校验，失败只重试下载。保留可复用的旧安装包用于增量更新；不要为了清理更新缓存而删除整个用户数据目录。

这轮不把下载临时文件移到安装目录：Windows 的 Program Files 和 Mac 的应用包可能只读，写入还会影响签名或需要管理员权限。沿用已有安全位置更能保证覆盖升级和老玩家存档稳定。

家具沿用原存档的 `room.owned` 和 `room.placed`。旧家具的 `id/x/y` 继续有效；新副本只增加可选的 `instanceId`、`scale` 和叠放顺序 `order`，移动、缩放或收回只作用于所选的一件。同款家具购买解锁一次后可以重复摆放。重启、导出和导入都会保留各件家具的位置与大小，不会重建拉姆或清空回忆。
