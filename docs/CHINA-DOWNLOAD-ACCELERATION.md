# 国内下载加速建议

调研日期：2026-10-29。本轮没有开通云服务或切换正式更新源；客户端仍使用本仓库 GitHub Releases。

## 推荐方式

使用项目自己控制的对象存储和下载域名，镜像正式版的版本清单、安装包、分块索引和校验文件，客户端优先通过下载域名获取，GitHub 保留为备用下载来源。首次安装的下载页也提供相同的加速链接，才能覆盖不会使用 GitHub 的用户。

| 现有条件 | 建议 | 需要核实的地方 |
| --- | --- | --- |
| 已有备案域名 | 中国内地 OSS/COS + 国内 CDN | 三网下载、单区间 Range、流量费用 |
| 暂无备案域名 | 先评估香港对象存储 + 境外 CDN/自有域名 | 跨境访问仍受实际网络影响，需要国内实测 |
| 已有 Cloudflare 服务 | 可评估 R2 + 自定义域名 | 国内速度没有保证；`r2.dev` 官方定位为开发用途且有限流 |

阿里云 OSS 与腾讯云 COS 均有字节范围下载能力。腾讯云文档明确：COS 支持 `bytes=first-last` 单区间，不支持多区间。本项目的增量预览已选择单区间请求。

按照腾讯云当前公开接入说明，选择中国境内或全球加速需要备案域名，选择中国境外加速不要求备案。具体接入条件和收费以开通时的服务规则为准。

## 同步与客户端切换

1. 在本轮正式发版获确认后，由 GitHub Actions 把最终安装包及对应索引同步到对象存储。云端写入凭据放在 Actions Secrets，客户端只需要公开下载地址。
2. 每个平台、架构和版本使用固定目录，例如 `releases/v0.x.y/`；同一版本的文件保持字节一致，沿用相同 SHA256/SHA512。
3. 文件上传并检查完成后，最后更新版本清单，避免用户发现新版时安装包尚未就绪。旧版本分块索引继续保留，以支持跨版本升级。
4. 客户端需要同时支持从镜像检查版本和下载文件。仅镜像 EXE/DMG，检查版本仍依赖 GitHub，无法解决完全连不上 GitHub 的用户。
5. GitHub 继续作为备用源。切换下载来源时重新核对版本和文件哈希；未通过校验的内容不能复用为增量基准。

这一部分需要后续接入真实的存储桶和域名，并完成端到端测试。本轮没有在代码中写入未验证的镜像地址，也没有把下载凭据发给客户端。

## 无云服务时的临时办法

可在下载说明中提供项目所有者上传的国内网盘安装包链接，方便首次安装。自动更新仍需要稳定的 HTTPS 文件地址和 Range 支持，不能直接把需要网页跳转、登录或短期令牌的网盘分享页当成更新接口。

## 配置要点

- 开启 HTTPS、单区间 Range 和返回正确的 `206` / `Content-Range`。
- 安装包和 `.blockmap` 保持原始字节，不启用会改变内容或分块偏移的压缩/转换；尤其不要把已经 gzip 的 blockmap 当作需要自动解压的 HTTP 内容。
- 版本化安装包、索引可长期缓存；`latest`、兼容版频道及 Mac 更新清单使用短缓存并在发版时刷新。
- 配置适用于大文件的分片回源；将源站与主要加速区域合理部署，减少跨境回源。
- 资源清单和五种平台配置一并验证，不能把 Windows 兼容版指向常规版，也不能混用 Mac 架构。

不建议把公共 GitHub 代理作为默认更新源：服务可用性、文件大小限制和 Range 支持难以持续验证。增量本身减少流量，受控的下载源解决连接速度，两者需要一起做好。

## 接入后的验收

应在国内电信、联通、移动网络测试首次完整下载、增量更新、断网重试和 GitHub 回退，记录首字节时间、实际速率与传输字节。当前云环境的联网测试不能代表国内三网速度，也不能据此承诺具体提速倍数。

需要准备：项目所有者的云服务账号/存储桶、下载域名；使用中国内地 CDN 时准备已备案域名。账户和密钥只通过服务商控制台与 GitHub Secrets 配置。
