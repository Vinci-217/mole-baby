# 素材加载、占位文本与存档保护检查

本次针对 v0.33.3 的本地问题修复，仅提供私有测试包；不更新公开 Release、版本标签或自动更新渠道。

## 已确认的加载原因

- 桌面安装包已内置全部运行素材。装扮通过本地 `ram-original:` 协议读取 SWF，网页预览才走 HTTP；慢加载不等于每次从网上下载素材。
- 换衣曾因 React iframe 的 key 包含素材 ID 而重建整个 iframe。实测初次载入后连续换三件衣服，WASM 请求数由 1 增到 4；本机每件等待约 1.5～2 秒。
- 原协议重复读盘、并发请求未合并；普通拉姆的首帧还等待进食、洗澡、睡眠、摸头、拖动等所有图集完成染色。
- 服装控制器注册完当前站立姿态后，宿主又重复选择同一姿态，额外等待 12 个源帧稳定。

当前实现复用 iframe 和 WASM 模块，对本机原始字节采用 64 MiB 有界缓存并合并并发读取；最多保留当前装扮和上一个已成功载入的装扮播放器。旧播放器静音并暂停，各自保持独立 AVM，避免官方导出类冲突。普通拉姆只等待当前动作实际需要的完整图集，站立显示后再预热拖动素材。没有删帧、降分辨率或改写官方原件。

首次打开一件未缓存的原始 SWF 仍需要解释时间轴与注册骨骼；诊断日志保留 load / boot / progress / ready 耗时，不能承诺每台机器瞬间载入。测量结果见运行后生成的 `artifacts/loading-save-review/`。

## 拖动时的问号

原库含有名字占位 TextField。原控制器仅在 ENTER_FRAME 清理，方向变化的嵌套帧脚本可以在其后重建文本，造成绘制前短暂可见。适配控制器新增 EXIT_FRAME 清理及方向切换后的即时清理；提供 `previewTextCount` 用于真实播放器回归，检查拖动与切换方向没有可见文本字段。

原始 SWF 仍保留在 `public/assets/original/official/files/`。修改的是 `controller.swf` 适配层；通过 `python3 scripts/art/build-ram-controller.py` 从已有原件重建。

## 存档与恢复

- 沿用 Chromium 用户数据目录，不移动、清空或合并旧存档。启动优先识别实际存储目录，固定已经选择的目录，避免仅有窗口设置的目录遮挡旧记录。兼容版与现代版保持隔离，显式 QA 配置不影响玩家目录。
- 桌面版在 `<userData>/save-backups/latest.json` 写入独立、原子替换的完整备份。一个新会话第一次写入前保留上一份记录；导入、更新前写入独立时间戳快照。损坏的旧备份也会原样存档，没有自动清理历史备份的逻辑。
- 主存档缺失时，在 React 挂载和领养流程之前恢复同目录备份；非空但损坏的主存档不会被自动覆盖。用户明确送别后，通过送别标记阻止自动恢复这只拉姆，避免删后重新出现。
- 设置、领养入口及损坏存档提示页都可以检查本地记录。桌面版显示真实存档、备份及旧版本路径，提供打开目录、导入备份功能；网页端说明存储与浏览器/访问地址绑定，不伪造本地路径。
- 导出 JSON 包含身份、颜色、成长、衣橱、背包、小屋、留言与回忆，并携带可迁移的偏好设置；旧 JSON 仍可导入。导入失败会回滚阶段性写入，保留原记录。自行导入的音乐文件仍属于 IndexedDB 数据，不包含在 JSON 内。

## 全量和差量更新

差量更新是在独立更新缓存中重建完整安装包，经过校验后再交给平台安装器；没有原地修改存档的步骤。全量和差量的缓存清理只允许操作下载包目录，不能指向用户目录、Local Storage 或 save-backups。

Windows 自动安装前需要渲染进程保存成功并写入备份。Mac 手动打开 DMG、Windows 便携版打开安装包前，现在也要完成同一存档检查；失败时不启动安装包。NSIS 保持 `deleteAppDataOnUninstall: false`。Windows 全量更新留下的旧索引若与本地基线大小不匹配，下次差量先刷新索引，避免因此无谓地转成全量。

安卓另查到启动镜像合并会移除“原生 SharedPreferences 没有、WebView 仍有”的旧键。现在改为保留这些键并补写原生镜像；只有明确的删除标记才从 WebView 移除记录，镜像写入失败也保留浏览器中的原始记录。APK/素材更新的临时清理仍限于更新包或素材目录，与 PetStore 分开。

安卓本轮已运行 4 项前端镜像合并检查及 17 项 Java 差量/真实 HTTP 传输测试。完整 Gradle 单元测试因当前环境缺少 Android SDK 未运行成功，新增 PetStore 原生重启/删除标记回归需在具备 SDK 的 Android 构建环境执行；本轮不发布 APK，也没有手机实机验证结论。

回归覆盖：差量下载、全量下载、校验失败、取消下载、安装前备份失败，以及两种下载完成后主存储和独立备份字节保持一致。Windows Actions 分别运行真实 NSIS 差量/全量安装与重启测试。

## Windows exe 与入口

主程序仍是安装目录的 `拉姆.exe`，必须连同 resources、locales、DLL 使用。安装完成会检查主程序存在、可读且大小正常，并检查 app.asar；不完整时中断安装，不能报告成功。桌面、开始菜单和安装目录的快捷方式按最终目录重建；另写 `安装入口检查.txt` 记录实际入口。

私有 Windows 构建检查真实 PE、完整 ZIP、交互式安装、点击三个真实快捷方式启动，以及人为破坏快捷方式后的覆盖修复。若玩家安装后 exe 再次消失，还需要这台机器的安装目录和 Windows 保护历史才能确认原因，不能把所有个案都断言为同一个安装器问题。不要建议玩家删除存档或关闭安全防护。
