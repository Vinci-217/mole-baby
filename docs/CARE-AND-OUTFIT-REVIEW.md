# 进食、穿衣缓存与桌面拖动

本轮修改位于本地预览分支，不更新正式 Release 或自动更新渠道。沿用原应用标识、存档键和用户数据目录。

## 原版照料动画

`src/original-care.ts` 统一解析实际消耗的用品和成长形态。初级、中级、高级分别使用页游 `pet2`、`pet3`、`pet4` 的原片；经典超级、神力超级及水火木形态按既有规则共用 `pet101` 的官方照料原片。穿衣的临时外观形态不参与选择进食原片。

已有完整帧导出的原片直接播放本地图集，按原帧顺序、帧率显示；没有帧导出的原片使用已打包的 SWF 播放器。照料期间仅隐藏、暂停已加载的衣服播放器，结束后恢复同一个播放器，不重新加载衣服，不改变成长或穿戴记录。静止、摸头和拖动不会因遗留的用品 ID 被误判为进食。

素材库中的以下缺失项使用同形态的官方同类原片，明确属于共用素材，不冒称找到了该食品独有的原片：

| 食品 | 缺失范围 | 共用官方原片 |
| --- | --- | --- |
| 奶油鬼脸匹萨 `180067` | 中级 | 火腿三明治 `180020` |
| 怪味南瓜汁 `180068` | 中级 | 胡萝卜汁 `180021` |
| 拉姆能量星 `180071` | 现存档案只有图标 | 云朵面包 `180070` |
| 优质牛奶 `180073` | 现存档案只有图标 | 麦香牛奶 `180002` |

其他阶段存在对应原片时优先使用对应原片。满满精力饮料沿用原来的运动可乐 `180014` 原片。种子期不能穿衣，继续保留现有种子照料方式；原始档案没有种子食品 SWF，不能宣称存在该套原片。所有用品的存档 ID、数量扣除和效果保持原规则。

背包只在悬停、键盘聚焦或按下某个用品时准备它的本地动作，不批量解码所有图集。

桌面原片的预加载通道 `ram-original:` 明确加入 renderer 的 `connect-src`，修复它先前被 CSP 拦截的问题。该协议只读取安装包中的白名单文件，保留路径检查、容量上限和并发读取合并；远程脚本与 `eval` 继续受限。

## 穿衣外观缓存

缓存按原片 SHA-256、原片形态、真实身体注册形态、颜色和画布版本区分，保存在独立的 `ramu-original-frame-cache-v1` IndexedDB 数据库，带固定容量上限。新截图会通知等待的显示位置；并发读取合并，旧磁盘读取不能覆盖新截图。缓存失败只影响加速，不影响玩家存档。

个人状态头像使用已缓存的真实原片截图，避免为静态头像再次启动完整播放器。桌面、走路、拖动和试衣镜继续播放实时原片；重开时截图只覆盖播放器准备阶段，不替代动画。首次遇到未缓存的衣服仍需准备一次原片。

## 桌面拖动

原逻辑把“正在照料／玩耍”同时用作禁止拖动条件，因此穿衣后遇到未结束的用品动作时无法拾起。现在移动超过拖动阈值后，会中断临时表演、释放其临时绘图区域，再启动原生窗口拖动。已经保存的用品扣除和照料效果不撤销，原片的延迟完成事件也不能结束新的拖动状态。

按下后马上松开仍按点击处理；看书计时、睡眠、外出、打工和缩放编辑期间继续遵守各自的交互限制。鼠标已经松开时，延迟返回的原生准备请求不会再启动拖动。

## 验证入口

```sh
npx vitest run src/original-care.test.tsx src/uploaded-actions.test.ts src/outfit-preview-cache.test.ts src/components/outfit-action-fallback.test.tsx --maxWorkers=1
node scripts/care-outfit-regression.cjs
xvfb-run -a -s '-screen 0 1800x1100x24' node scripts/care-outfit-native.cjs
```

浏览器回归检查八种成长形态、完整原片帧推进、衣服播放器复用以及缓存重开。原生回归使用独立且复用的 QA 存档，断开 HTTP 网络后用真实 X11 鼠标测试火焰羽翼、皇冠猫耳、木叶头冠的静止拾起和进食中途拾起，再检查看书禁止拖动和重开后的身份、成长、穿戴记录。

本地 Windows 安装包另核验 PE、全部已封装素材哈希、NSIS 启动 CRC 和安装器容器完整性。当前云电脑为 Linux，原生 Windows 安装及快捷方式仍需在 Windows 电脑上验收。
