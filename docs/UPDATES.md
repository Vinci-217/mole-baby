# 自动更新

从 v0.29.1 开始支持。v0.28.0及更早版本没有更新代码，需要先手动安装一次最新正式版；更新保留原本的本地宠物、物品、装扮、偏好和回忆。

## 每次打开会发生什么

默认开启自动更新，且没有在设置里手动关闭时：

1. **完全退出后重新启动**：每次启动约8秒后检查本仓库的最新公开正式版。上次检查是最新版，也不会跳过这次启动检查。
2. **有更高版本**：后台下载并校验安装包。没有新版本时继续使用当前版本，不重复安装。
3. **Windows安装版**：下载完成后约8秒检查空闲状态，忙碌时继续等；空闲后先取得存档成功回执，再静默安装、重启。权限受限的安装目录可能仍需要Windows确认。
4. **当前Mac本地签名版 / Windows便携版**：自动检查、下载，随后在设置或托盘提供「打开更新安装包」。当前Mac不能直接静默替换应用，需要手动安装。

关闭窗口只是缩到托盘，属于同一个运行进程；从托盘恢复也会检查，但两次自动检查至少间隔5分钟。关闭「启动时自动更新」会保存在本地，之后启动不会自动检查、下载或重启；仍可手动检查。网络失败会继续使用现有版本，开启自动更新时约30分钟后重试。

**检查的是GitHub Releases，不是代码提交。** 预览分支、README里的GIF、草稿和预发布都不会成为当前客户端的更新版本。只有更高版本的公开正式版才会触发更新；相同版本号不会重复安装。

| 系统与安装方式 | 每次启动检查 | 有新版自动下载 | 自动安装并重启 |
| --- | --- | --- | --- |
| Windows 安装版 | 是 | 是 | 空闲、存档成功后自动执行 |
| Windows 便携ZIP | 是 | 是 | 需打开安装包 |
| 当前Mac本地签名版 | 是 | 是，按Apple/Intel架构下载 | 需打开DMG手动替换 |

对应实现为 [electron/updates.cjs](../electron/updates.cjs)，启动、托盘唤起与存档接线在 [electron/main.cjs](../electron/main.cjs)。[自动更新测试](../electron/updates.node-test.cjs)覆盖两次独立启动分别检查、保存的关闭偏好、空闲等待、存档失败阻止安装及Mac校验失败。

## Windows安装版

启动约8秒后在后台检查本仓库的最新正式版，不需要GitHub Token。发现新版后下载并校验；桌宠空闲时先保存数据、等待渲染器存档回执并刷新本地存储，然后静默安装、重启。正在玩游戏、专注计时、使用用品或操作小屋时等待。也可以在托盘或小屋设置中立即更新；真正退出应用时可安装已下载的更新。

关闭窗口仍然收进托盘，托盘「退出拉姆」才退出。重新打开托盘窗口也会触发检查，自动检查有5分钟间隔以免重复请求。网络失败保留当前版本，提供手动重试，自动模式下稍后重试；不安装校验失败、预发布或旧版本。

小屋设置里的「软件更新」显示当前/目标版本、下载进度，提供「检查更新」「下载更新」「立即更新并重启」和「启动时自动更新」开关。关闭自动更新会取消待执行的自动重启；已开始的下载可以完成并保留，之后需手动安装。

每用户安装可自动完成；安装到管理员控制的位置时，Windows可能要求系统权限确认。便携ZIP会检查和下载安装包，但不会静默把解压目录改为安装目录；打开安装包安装后即可获得安装版自动更新。

## Mac

本地签名的现有Mac包可以自动检查、核对SHA256并下载对应Apple芯片/Intel的DMG；下载后在设置或菜单中打开安装包，完成替换。不会绕过Apple验证或假装本地签名支持Squirrel静默替换。

GitHub构建配置完整的Developer ID证书与Apple公证Secrets后，会在包内标记支持标准签名自动更新，使用合并的`latest-mac.yml`选择架构并交由系统标准更新机制处理。实际签名/公证状态仍以发布页与Mac信任回执为准。

## 发布约定

生产更新源固定为本仓库公开的GitHub Releases。Windows/已签名Mac使用electron-updater，直接读取`releases/latest/download/`下的更新文件，无需GitHub API凭据；本地签名Mac使用最新正式版的DMG和SHA256SUMS。渲染器不接收或传入任意更新URL、安装文件路径或版本。

发布前必须具备：

- Windows `latest.yml`，指向当前NSIS安装包。
- 合并的`latest-mac.yml`，包含arm64/x64的ZIP与DMG。
- 六个成品的SHA256校验；元数据包含实际大小与SHA512，并在发布阶段重新核对。

流程先检查元数据和全部成品，再创建草稿、上传完整附件，最后公开发布并设为latest，避免客户端看见缺少安装包/更新文件的正式版。

## 验证

规则覆盖并发检查去重、新版本/预发布/降级、忙碌等待、存档失败阻止安装、自动更新偏好、便携版模式、Mac架构与SHA256失败清理、网络失败及重试。

生产成品检查更新设置/IPC和真实渲染器存档回执。Windows额外构建同一更新模块的1.0.0与1.0.1安装夹具，从本地测试源执行检查、下载、静默安装、自动重启，并检查新程序版本、存档回执及宠物数据原样保留。测试夹具、测试源与安装路径均隔离，不会发布这些夹具安装包。
