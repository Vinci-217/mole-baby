# 软件更新

从 v0.29.1 开始支持。v0.28.0 及更早版本没有更新代码，需要先手动安装一次最新正式版；更新保留本地宠物、物品、装扮、偏好和回忆。

## v0.31.7 起自动选择下载策略

「增量／差量」都表示复用旧安装包中仍然相同的内容，只下载需要变化的部分。新增素材、修改或删除文件、内容移动和跨版本更新均由新旧包的分块索引计算；客户端不必依次安装每一个中间版本。下载后重组成完整的新安装包，校验通过并经用户确认后再安装，宠物存档不会被当作补丁对象。

小屋设置 →「软件更新 → 下载方式」提供：

- **自动选择（默认）：** 有匹配的旧包时先比较差异，合并相近的小请求；变化较多、请求开销过大或无法复用时直接完整下载。差量下载遇到网络不支持 Range、索引损坏或校验失败时，自动回退完整包，界面显示原因。
- **完整包：** 跳过差量计划及索引请求，适合网络不支持分段下载等情况。同一目标版本已经校验过的完整缓存仍可复用。这个设置保存在本地；修改它不会授权下载或安装，也不会改动正在传输的更新。

当前 Windows NSIS 与本地签名 Mac DMG 共用同一差异规划策略。相隔不超过 64 KiB 的下载段会合并；当变化内容达到 90%、请求超过 512 次或计入请求开销后接近完整包大小时，选择完整下载。以上是传输方式的自动判断，不改变版本发现、下载确认、存档检查和安装确认。标准签名 Mac 的 ZIP 更新继续使用 electron-updater 的原生差量及完整回退，选择「完整包」时同样关闭差量。

Windows／兼容版／Mac 各架构仍使用独立、固定的正式更新渠道；不会向用户索取任意补丁地址。发布过程继续为完整成品生成索引，历史版本的包和索引保留，用于直接跨版本比较。没有匹配缓存时仍需要完整下载，不能承诺每次更新只下载几 MB。

旧客户端首次升级到 v0.31.7 时使用它原有的更新逻辑；安装后，后续更新才会使用这里的自动策略与本地偏好。

## v0.31.4 起支持增量下载

本版将已完成自测的增量更新纳入正式构建：Windows 安装版支持 NSIS 分块下载，当前 Mac 本地签名版支持 DMG 分块还原；发布附件包含对应分块索引。旧客户端的下载行为由其原有代码决定。

安装包下载优先复用匹配的旧包；没有旧包、索引不可用、Range 不支持或增量校验失败时回退完整下载。还原后的完整文件必须通过校验，下载和安装继续分别确认。设置中显示增量/完整下载、当前传输字节和复用量。这里的传输字节指安装包数据，少量索引与版本清单另有网络开销。

旧客户端首次升级到支持增量的版本仍可能完整下载一次。通过应用内更新下载过的 Mac DMG 可作为下一次的基准；从浏览器手动安装或清理缓存后，可能需要一次完整下载来建立基准。Mac 下载完成后仍需替换应用，分块下载不会改变安装方式。增量减少下载量，最终安装体积和暂存空间需求另行计算。

当前继续使用 GitHub Releases，本轮不接入国内镜像。实现、测量与验证范围见[增量自测记录](INCREMENTAL-UPDATES-PREVIEW.md)。

## 发现新版本后先确认

默认开启「启动时检查更新」：

1. 完全退出后重新启动，每次启动约 8 秒后检查本仓库的最新公开正式版。上次检查为最新版，也不会跳过本次启动检查。
2. 发现更高版本时，显示包含版本号的确认提示，提供「下载更新」和「稍后提醒」。只有选择下载才会下载安装包；取消、关闭或选择稍后会继续使用当前版本。
3. 下载完成并校验通过后，再询问是否安装。Windows 安装版及支持标准更新的签名 Mac 版提供「更新并重启」，确认后先取得存档成功回执，再执行安装。当前 Mac 本地签名版和 Windows 便携版提供「打开安装包」，由用户完成安装。
4. 选择「稍后更新」后继续使用当前版本，可在小屋设置或托盘再次确认安装。不会等空闲时自行安装，也不会在退出拉姆时自动安装。

每个进程对同一版本的下载和安装各自动提示一次，避免重复打断。用户仍可从设置或托盘主动打开确认提示。提示默认选择「稍后」，按取消或关闭不会授予同意。

关闭「启动时检查更新」会保存在本地，之后启动不再自动检查；仍可手动检查。旧版本保存的更新开关只控制是否检查，不会授予新版本下载或安装权限。重新打开检查开关，也不会下载或安装待处理的更新。

关闭窗口只是缩到托盘，属于同一个运行进程。从托盘恢复也会检查，两次自动检查至少间隔 5 分钟。网络失败继续使用当前版本；开启启动检查时约 30 分钟后重试，仍需用户确认才下载或安装。

**检查的是 GitHub Releases，不是代码提交。** 预览分支、README 中的 GIF、草稿和预发布不会成为当前客户端的更新版本。只有更高版本的公开正式版才会被提示；相同版本号不会重复安装。

| 系统与安装方式 | 启动检查 | 下载前确认 | 安装前确认 |
| --- | --- | --- | --- |
| Windows 安装版 | 默认开启，可关闭 | 是 | 是，确认后保存并更新重启 |
| Windows 便携 ZIP | 默认开启，可关闭 | 是 | 是，确认后打开安装包 |
| 当前 Mac 本地签名版 | 默认开启，可关闭 | 是，按 Apple/Intel 架构下载 | 是，确认后打开 DMG 手动替换 |
| 标准签名 Mac 版 | 默认开启，可关闭 | 是 | 是，确认后保存并更新重启 |

## 校验与存档

Windows/标准签名 Mac 使用 electron-updater。`autoDownload` 和 `autoInstallOnAppQuit` 始终关闭，检查本身只发现版本；明确确认后才调用下载或安装接口。Windows 安装版在安装前要求渲染器存档回执并刷新本地存储；存档失败不会退出或调用安装器，可稍后重试。管理员控制的安装位置可能仍要求系统权限确认。

本地签名 Mac 下载对应 Apple 芯片/Intel 的 DMG，核对 SHA256 后才允许打开。不绕过 Apple 验证，也不假装本地签名支持 Squirrel 静默替换。标准签名版的实际签名/公证状态以发布页与 Mac 信任回执为准。

生产更新源固定为本仓库公开的 GitHub Releases。Windows/标准签名 Mac 读取 `releases/latest/download/` 下的更新文件，无需 GitHub API 凭据；本地签名 Mac 使用最新正式版的 DMG 和 SHA256SUMS。渲染器不接收或传入任意更新 URL、安装文件路径或版本。

## 发布约定

发布前必须具备：

- Windows `latest.yml`，指向当前 NSIS 安装包。
- 合并的 `latest-mac.yml`，包含 arm64/x64 的 ZIP 与 DMG。
- 兼容版 `legacy-x64.yml`、`legacy-ia32.yml`，各指向对应架构的兼容安装包。
- 十个成品（常规Windows两个、兼容Windows四个、Mac四个）的 SHA256 校验；元数据包含实际大小与 SHA512，并在发布阶段重新核对。
- 三个 Windows 安装包、两个 Mac ZIP 和两个 Mac DMG 的七份 `.blockmap`，从签名/公证后的最终文件生成，与成品一并校验和上传；历史版本索引继续保留。

先检查元数据和全部成品，再创建草稿、上传完整附件，最后公开发布并设为 latest，避免客户端看见缺少安装包/更新文件的正式版。发布遵循仓库审批约定及用户当前明确指令。兼容包和存档目录见[Windows说明](WINDOWS.md)。

本版确认流程只能约束本版及后续客户端。尚未升级的旧版本仍使用原有更新逻辑，可手动安装本版后获得新的确认流程。

## 验证

[更新状态机测试](../electron/updates.node-test.cjs)覆盖启动检查、关闭偏好、发现新版不下载、下载与安装分别确认、退出不安装、并发检查去重、存档失败阻止安装、便携版模式、Mac 架构与校验失败清理、网络错误及重试。

[原生确认测试](../electron/update-prompts.node-test.cjs)覆盖确认/稍后/取消、同版本提示去重、过期提示不得更新其他版本、原生对话框失败不更新，以及再次手动打开确认。

生产成品检查更新设置/IPC 和真实渲染器存档回执。Windows 安装夹具需显式调用确认接口后才下载和安装，不能把自动检查视为同意更新。测试夹具、测试源与安装路径均隔离，不发布夹具安装包。

## v0.30.2 Mac 网络回退

本地签名 Mac 先检查最新正式版跳转；若网络不支持 HEAD 或未返回可验证的版本地址，回退 GET 读取同仓库 `latest-mac.yml`，再核对当前架构 DMG 的 SHA256。网络失败时可从设置的「打开下载页」取得安装包。检查、下载和安装仍各自遵守已有确认规则；打开 DMG 后需要把应用替换到原安装位置。

v0.30.4起版本、校验文件与下载请求不复用旧HTTP缓存。Mac 成品联网测试从真实8秒启动计时器开始，检查暂缓/确认下载、SHA256，以及实际挂载下载DMG后应用的版本号。测试不会替换运行中的应用，不能等同于验证静默安装。

如果Mac显示已下载却还是旧版本：点击「打开 DMG 安装」，把「拉姆」拖到「应用程序」并选择替换，从状态栏退出旧拉姆，再从「应用程序」重新打开。仅关闭窗口会缩到托盘；仅打开DMG也没有完成应用替换。若使用的是v0.29.1之前版本、关闭了启动检查，或网络无法连接GitHub，需要从发布页手动安装一次。
