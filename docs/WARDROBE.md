# 拉姆装扮：已实现范围与扩展方式

装扮可实现。v0.22 第一版已经提供小屋里的「衣橱」：先试戴，使用摩尔豆购买后穿戴，可换回原来的样子；购买永久拥有，不按次消耗。种子到四种神力形态、四种身体颜色均使用同一份衣橱。离开小屋、重启、导出/导入存档和手动切换阶段都会保留穿戴。桌面仍保留原七个入口，衣橱和购买在小屋里。

首批三件是原客户端配饰图形：庆生小帽、金色羽毛、紫色魔法帽。名称和30/45/60摩尔豆价格是本地设计，未声称核实了原服务器商品名或定价。来源与哈希见 [wardrobe/source.json](../public/assets/original/wardrobe/source.json)。这是一个头饰位，换一件会替换另一件，默认不穿戴；没有把头冠或身体换成另一个角色。

## 如何实现

1. **独立的配饰图片。** 从原 SWF 的完整 sprite 导出透明 PNG，避免导出整个舞台时裁掉帽檐。拉姆的原身体、眼睛、叶片和配色不重画；配饰保留自己的原色。
2. **跟着每一帧身体走。** 用现有身体颜色遮罩计算当前身体位置、宽度与变形，眼睛方向用于轻微旋转。配饰放进与身体相同的动作层；种子放在独立身体层，花盆保持直立。玩球使用原球与身体的同一图集和视口变换，配饰跟随相同帧。无身体的帧隐藏配饰。
3. **保存实际所有权。** `GameState` 增加可选的 `wardrobe` 与 `wearing`，保留版本1旧存档；读取时去重、剔除未知款式，未拥有的不能穿。购买立即检查最新存档中的豆数和所有权，连续点击只扣一次。
4. **试戴与穿戴分别处理。** 镜子里的试戴是面板临时状态，既不扣豆也不写入穿戴。确认购买、确认穿戴才保存；这些真实事件才会进入陪伴回忆。换装不增加成长或照料数值。
5. **用真实画面验证。** 检查各阶段、颜色、正常/减少动态效果、静止换装、跳起踩球和睡眠；身体图像在穿戴前后应完全一致。成品检查覆盖购买、重启和心情回应。

## 后续适合增加什么

头饰可继续增加发带、小花和眼镜，但眼镜需要检查睁眼/闭眼的遮挡；饰物不能遮住辨认拉姆的关键轮廓。种子也适合花盆挂饰，挂饰应固定在盆层，不跟着身体晃动。

披风、围巾和全套服饰需要前后分层以及转身、飞行、吃东西、睡觉、玩球各姿态的对应素材。当前三件是平面配饰，按身体帧适配位置、缩放和旋转；没有实现衣料模拟、背面专用图或完整套装。下一批套装应先完成这些姿态及遮挡，再接入多部位穿搭和套装组合，不能拿一张正面衣服覆盖所有动作。

可用现有小游戏奖励的摩尔豆购买新款；后续也可以设计节日或陪伴纪念装扮，需要明确领取条件与真实领取记录。当前没有虚构官方活动、额外成长数值或付费功能。
