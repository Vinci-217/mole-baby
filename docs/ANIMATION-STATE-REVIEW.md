# 动画状态与服装审查 · 2026-11-12

本轮基于 `preview/v0333-wardrobe-audit`，处理穿衣后摇晃突然显示超级形态，以及同类动作的服装、时钟和状态切换问题。

## 已确认的原因与修改

| 问题 | 原因 | 修改 |
| --- | --- | --- |
| 穿衣后摇晃显示裸身超级形态 | `outfitSupportsAction` 没有包含 `dizzy`，`ClothedRam` 因此隐藏服装，显示真实成长形态的裸身动画 | 所有普通动作保留完整服装原片，由共用动作适配层补齐缺失动作 |
| 睡觉、心情、阅读、照料时临时脱衣 | 与眩晕相同的白名单和回退路径；旧测试也要求这种行为 | 移除普通动作回到裸身的路径；阅读书本道具与魔法书服装保持独立 |
| 眩晕有两套结束时间 | `DesktopCompanion` 自行维护 shaking 和计时器，App 也管理 dizzy | 桌面只发送摇晃事件，App 与角色播放器统一驱动动作 |
| 中断或换装后旧回调结束新动作 | 各播放器的结束和失败回调没有统一的动作代次校验 | `Ram` 入口按宠物、形态、服装、颜色、动作、动作 ID、用品建立播放代次，旧回调失效，每代只结束一次 |
| 上一次用品影响新动作 | 中断后残留的 itemId 仍可能优先选用品原片 | 统一动作优先级，用品只参与照料动作选择，睡觉/眩晕/拖动优先 |
| 动作加载后没完整播放或奖励计时不一致 | 加载时间可能消耗播放时间，服装适配时长与旧用品时长不同 | 在服装 ready 后启动动作钟；App、用品锁定与玩耍奖励使用同一动作计划 |
| 素材重试时提前播放 | 同一服装播放器重试时仍保留上一次 ready 标记，复现为素材未加载但动作已播放 650ms | 每次加载/重试重新设置 ready；加载期间暂停动作钟，过期服装加载不能结束后续动作 |
| 裸身备用眩晕路径不能可靠结束 | 备用 `DizzyFrames` 没有结束回调，部分形态还会误选普通图集 | 使用独立眩晕图集、加载后计时，正常/减少动态模式均结束一次 |

## 统一规则

- 优先级：睡眠 → 眩晕 → 拖动 → 标准化后的请求动作。
- 成长数据、服装外观、短暂动作分开处理。任何动作适配都不写入 growth、evolution 或 wearing。
- 官方只有初级穿衣原片时，仍使用完整初级穿衣外观与原走法，真实成长数据保留；脱下恢复真实形态。
- 种子阶段不穿戴，不读取衣服作为当前外观，已有所有权保留。
- 普通动作使用同一份已加载的服装播放器；方向改变使用该服装 SWF 自身的方向时间轴。
- 显式魔法在烟雾中显示原版目标，结束后显示同一份服装播放器。水、火、木和盒子内容入口保留。
- 有限动作有明确时长和结束回调；待机、行走、睡觉、专注等持续状态不被错误的有限动作结束信号打断。
- 切换动作时清理当前动作的属性、声音、RAF、计时器和事件监听；拖动弹性属性独立保留。

## 代码分工

| 文件 | 职责 |
| --- | --- |
| `src/ram-action.ts` | 统一动作别名与中断优先级 |
| `src/costume-action.ts` | 解析原版动作来源、动作分类、用品和时长 |
| `src/costume-motion.ts` | 按当前身体坐标计算项目适配动作，限定尺寸变形范围 |
| `src/components/Ram.tsx` | 选择穿衣或裸身路径，隔离旧动作的完成回调 |
| `src/components/ClothedRam.tsx` | 保留原版服装播放器，协调临时魔法目标 |
| `src/components/OfficialOutfitMotion.tsx` | 共用播放时钟、注册点、暂停、音效和完成生命周期 |
| `src/components/CareAction.tsx` | 裸身与穿衣共用的用品道具与接触节奏 |
| `src/components/OutfitActionCue.tsx` | 穿衣动作的书、足球、眩晕星星、弹簧、泡泡等道具层 |

素材说明：服装图像和方向原片仍来自本地原版 SWF；本轮没有改写原始素材，没有删帧、降低安装素材质量或加入远程下载。摸头、眩晕、穿衣足球、照料、玩具和自然动作中缺少官方穿衣片段的部分属于项目编排的适配，并非官方完整动作影片。原版裸体动作图集继续用于未穿衣状态。

## 验证与复现

自动测试：`npm test`，包含 65 个前端测试文件的 486 项测试，以及 170 项桌面、存储与打包测试。组合检查覆盖 122 件服装、8 种非种子成长形态、完整动作词汇、原版动作条目与所有照料用品；种子禁穿单独验证。

生产构建：TypeScript 和 Vite 均完成，等待无损素材处理及离线资源校验结束后才运行界面检查。

实际播放器验证：

```bash
node scripts/costume-state-machine-regression.cjs --sources-only
node scripts/costume-state-machine-regression.cjs --matrix-only
node scripts/costume-load-clock-regression.cjs
node scripts/costume-state-machine-regression.cjs --application-only
node scripts/costume-state-machine-regression.cjs --mobile
xvfb-run -a node scripts/costume-state-machine-regression.cjs --native
xvfb-run -a node scripts/wardrobe-native-quality.cjs
node scripts/record-costume-state-review.cjs
```

- 逐件加载全部 122 件服装，检查原片实际像素和眩晕、摸头、足球、睡觉、阅读、吃东西、弹簧这 7 类动作，确认没有重新创建或换掉服装播放器。
- 4 类代表服装 × 8 种形态，播放完整眩晕、摸头、足球、照料，检查动作结束、左右原版方向、身体注册点，以及上一个动作不会结束后一个睡眠状态。
- 原版水、火、木和魔术盒：检查变身目标和结束后的穿衣恢复。
- 实际 App 中重复摸头与指针摇晃；桌面/小屋/试衣镜/重新打开，核对原 QA 存档的身份、颜色、成长、服装所有权、用品和摩尔豆。
- Linux Electron 的本地自定义素材协议，以及浏览器 390px 手机布局。单独的原生指针测试阻断 HTTP，检查真实 X11 指针左右拖动、注册点和离线玩球。

测试记录保存在 `artifacts/costume-state-review/`；测试只使用隔离浏览器环境和命名 QA 档案，继续复用已有 QA 记录，不读取或清空玩家安装档案。
