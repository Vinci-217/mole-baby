# 拉姆餐厅（预览）

小屋下方的「餐厅」按钮进入；游戏面板和桌面「一起玩耍 → 去打工」也进入同一间餐厅。

1. 在菜谱里选菜，使用摩尔豆购买一批食材。每一道菜都可用豆获取，不需要种植、采集或会员。
2. 点击「开始营业」，灶台按在线营业时间烹饪。
3. 菜做好后点击灶台，把菜放上餐台。同种菜自动合并，餐台种类有容量限制。
4. 客人到店入座，空闲拉姆自动取餐、端盘送餐，再空手返回。顾客吃完付款，只结算一次。
5. 经营获得经验，解锁菜品、员工名额与内饰。账本记录营业额、投入、净收益和荣誉。

退出餐厅、程序关闭、断网、手机进入后台或计时器因挂起中断时自动打烊。重新打开需要手动营业；没有离线收益，也没有离线工资。未完成的订单退回餐台，已完成的收入保留。烹饪保存剩余营业时间，离线不会做好或烧糊。

## 内容与适配

- 72 道原客户端常规菜谱，使用原菜名、份数、基础售价及星级门槛。两条无法制作的占位条目不在其中。
- 72 张原菜谱图、72 张原成品菜盘、15 套原内饰，灶台、餐台、座位坐标来自各自的原 SWF。
- 原空手/端盘制服、实际方向动作帧、原顾客 16 帧进餐动作；背景音乐与五种餐厅音效沿用原模块。
- 60 级经验表、随等级提高的员工容量。招募帮手、换内饰和所有菜品统一扣小屋钱包的摩尔豆。
- 原耗材料、豆价为零的菜，适配为每批销售总额的 50%（至少 10 豆）。其余保留原批次豆价。
- 原烹饪时长除以 60，限制为 10 秒至 4 分钟；做好后的保鲜期为原时长除以 60，限制在 1 至 10 分钟。界面显示实际采用的本地时长。
- 原 Condition=401 的特殊菜改为 4 级解锁，不依赖原会员服务。员工招募费用为已有员工数 × 250 豆，一次性支付；没有原服务器的雇佣期限。
- 原始路径、校验值和转换说明保存在 `public/assets/original/restaurant/sources.json`。

这是基于原素材的本地经营玩法。在线表示程序正在前台营业且未断网，不要求登录摩尔庄园；不会连接官方游戏服务器。原版的真实好友雇佣、互访、全服排行、服务器活动和限时奖励尚未接入，不能视为官方客户端的完整替代。荣誉条件、路线、等待时长与经营结算由本项目适配。

## 存档

餐厅数据作为可选的 `restaurant` 字段随原宠物存档保存，存储位置与版本号不变；导出备份也包含这些数据。颜色、永久形态、回忆、家具、衣橱和背包沿用已有记录。

顾客与营业会话不会恢复。取走但尚未付款的餐食会另外记录预留数量；即使直接退出或程序中断，再次读取存档也会退菜，避免扣了库存却没有收入。旧版两分钟定时打工存档在打开时取消，不补发离线工资。上课的存档规则不变。

浏览器的 `?preview=restaurant` 是独立试玩入口，提供一只已长大的体验拉姆和 3000 豆。它使用单独的 `ramu-restaurant-review-v1` 存档，不读取或覆盖正式宠物档。桌面和手机客户端仍使用真实拉姆。

## 验证与素材复用

```sh
npm test
npm run build
node scripts/restaurant/verify-assets.cjs
node scripts/restaurant/browser-check.cjs  # 需要现有 localhost:5173 生产预览
```

素材补取与导出脚本位于 `scripts/restaurant/`；原件保持在 `local-assets/raw/`，新补取原件另放 `local-assets/research/restaurant-port/official/`。JPEXS 导出中出现的空白方向切换帧不加入可见行走循环；素材检查会逐帧检查实际播放序列与原进餐帧。

本轮在 Linux Chromium 验证桌面、手机宽度、完整成交、断网/后台打烊、重新载入、员工招募和独立试玩存档。Windows、macOS 与实体手机仍需本机验收；尚未推送或发版。
