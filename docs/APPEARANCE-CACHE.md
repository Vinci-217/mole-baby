# 小屋、桌面与成长外观缓存

## 重复载入的原因

切换小屋与桌面会卸载当前 React 显示组件。原来即使服装原文件和静态外观已缓存，组件中的 iframe 仍会被销毁，重新初始化 Ruffle/WASM、载入原片和注册身体，所以又出现“装扮载入中”。普通的 `appendChild` 移动 iframe 同样会重载其文档，不能当成复用播放器。

成长图集原来仅缓存少量内存中的配色结果；切换形态或动作后，图集可能被淘汰。再次读取虽不必联网，仍需重新解码中性图、蒙版并逐像素配色。

## 现在的处理

- `original-player-cache.ts` 用浏览器支持的 `moveBefore` 保留同一个 iframe 文档、WASM 与原片 AVM。离开显示位置时暂停时间轴、静音并暂存；返回时使用递增的请求序号恢复，旧请求不能覆盖当前动作。最多保留两个已就绪的闲置播放器，未完成或失败的播放器不会进入缓存。
- 不支持保留文档移动的浏览器（包括旧版 WebView/Windows 兼容版运行时）继续正常载入原片，以已缓存的完整外观图片衔接。不会用普通 DOM 移动冒充引擎复用。
- `growth-atlas-cache.ts` 保存实际完成配色的基础图集，使用无损 PNG，不减少帧数、尺寸或画质。种子、初级、中级、高级、经典超拉、神力超拉、水、火、木分别缓存，颜色、图集类型、像素尺寸和应用版本共同参与键值。只缓存已经实际使用的形态，不在后台批量解码全部素材。
- 缓存命中后直接读取配色图集，跳过中性图/蒙版解码和逐像素染色。首次配色仍从原素材生成；在首次绘制后空闲时编码缓存。缺失、损坏、配额不足或不可用时自动使用安装包原素材重新生成。
- 种子待机只准备待机图集，不再同时等待吃饭、睡眠图集。已缓存的服装外观衔接时不再重复显示载入提示；真正失败仍显示失败和重试入口。

缓存沿用独立的 `ramu-original-frame-cache-v1` IndexedDB，不改变玩家存档。压缩 PNG 内存缓存上限约 12 MiB/32 项，磁盘上限约 64 MiB/96 项；解码图集继续使用原有有限内存缓存。缓存淘汰只删除可重建的图片，不删除身份、成长、衣服、背包、留言或回忆。

## 回归

```sh
node scripts/appearance-cache-regression.cjs
node scripts/care-outfit-regression.cjs
xvfb-run -a -s '-screen 0 1800x1100x24' node scripts/care-outfit-native.cjs
```

独立动画页不读取玩家存档。回归记录在 `artifacts/appearance-cache-review/`；原生测试复用原来的专用 QA 档案，保留其身份和记忆。

本轮浏览器测试确认：三次卸载/恢复服装使用同一 iframe 文档及同一 AVM；重新加载页面清空模块内存后，阻断九种形态的原始中性图和蒙版，仍能使用 IndexedDB 配色图集逐像素一致地绘制。另测试缺少 `moveBefore` 的回退和恢复后走动。

Linux Electron 实际切换桌面/小屋六次，同一服装引擎被保留，除首次小屋布局与背景准备约 2.4 秒外，后续原片恢复约 128–150 毫秒。此计时来自云电脑测试，不作为各设备的固定耗时承诺。原生 Windows、Mac、Android 的安装和更新由发版流程分别验证。
